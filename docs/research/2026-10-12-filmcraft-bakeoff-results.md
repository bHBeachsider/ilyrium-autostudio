## 4. Where FilmCraft contradicted the assessment (correct the assessment, don't work around it)

1. **Clips are placed at native pixel size, not scaled to the sequence.** The first build put the
   768×432 Wan shots in a small box on black and center-cropped the 1088×1904 Kling shots. Every
   check except the pictures passed, so the A2/A3 criteria can't see this. Fix:
   `clip.fitToFrame {clips:[…]}` on every V1 clip. The adapter must always do this, and a QA frame
   look is the only gate that caught it. Pillarbox colour is black; the delivered
   `cut4_fixed_169` used white.
2. **Id prediction is only good for the one-item case.** Sequence id = 7 + number of imported
   items. Clip ids skip, because link groups consume ids (first place → `[18]`; next → `[20, 21]`).
   `make_cut.py` does a dry run of the placement steps, reads the ids, and bakes them into a
   static script. The real run's ids matched the dry run every time (12 runs).
3. **`essentialSound.generateDucking` takes only `{clips}`.** The `ducking.against / reduceDb /
   fadeS` parameters in assessment §1 don't exist on it. They are Essential Sound settings
   (`essentialSound.set key=ducking.reduceDb`), stored as `reduce_db / fade_s / against`.
   Defaults: Dialogue, −15 dB, 0.8 s.
4. **Clip times snap to the 24 fps grid; markers don't.** A clip requested at 5.670 s lands at frame
   136 (5.6667 s). A marker requested at 5.670 s stays at tick 1,440,270,720,000. That is under one
   frame off the cut; the adapter should quantise marker times.
5. **Image sequences import at 29.97 fps**, and the CLI has no way to reinterpret the rate. A
   24 fps Blender sequence would play 25% fast. Phase 1 needs either a frame-rate parameter
   upstream or `timeline.rateStretch`.
6. **Throughput on real media is better than the smoke for NVENC (16–21 fps vs 6) but still
   below realtime**, and it varies run to run (§3). With an explicit bitrate, NVENC holds it
   (11.5 Mbps for 12 requested), so the smoke's "1 Mbps" is purely a default.
7. Minor: `render` reports its timing on stderr ("rendered 1920x1080 in 262.2 ms"), not as JSON
   on stdout. FCP7 export folds clip gain into Audio Levels.

## 5. Open decisions (for Brad)

Assessment §9 decisions 1–4 are closed (see Decisions). Still open:

1. **Routing.** Accept FilmCraft NVENC as the master export for assembled cuts (75 s vs moviepy's
   328 s; −14.0 LUFS in one step), or follow the spec criterion literally (ProRes mezzanine +
   ffmpeg, measured slower here)? `delivery.py` cutdowns stay on ffmpeg either way.
2. **Go/no-go for Phase 1**, pending A7.
3. **Bed level + ducking stack.** moviepy's −16.48 dB bed gain and Essential Sound's −15 dB duck
   stack up to about −31.5 dB under VO. In Phase 1, pick one: either gain or ducking owns the bed
   level.
4. **Pillarbox colour** for mixed-aspect cuts: black (FilmCraft default) or white (as delivered in
   `cut4_fixed_169`)?
5. **`qc.py` on assembled cuts.** `freezedetect n=-60dB:d=0.4` flags low-motion AI takes once
   they're downscaled, and looping multiplies the flags. Run `qc` per take (as `qc_project`
   does) and not on masters, or loosen the threshold for masters?
6. **VO is overwritten in place.** Regenerating `shotN.mp3` destroyed the reproducibility of
   `cut_3`/`cut_4`. That breaks "takes are append-only" for audio. Also, `cut_4` was never
   recorded in `project.json`. One-off, so no FINDINGS row yet. Worth a VO-take scheme in Phase 2
   (the cut ledger).
7. **moviepy adds 1–2 frames per shot** (+5 over 5 shots). Fix it, or accept it as the reason to
   switch?

     `clip.fitToFrame`, not a per-clip effect.

     only, via a cut-mode flag in `qc`; the threshold is not loosened.
  5. **VO overwrite:** recorded as FINDINGS F-0006 (with the unrecorded `cut_4` as a second
     symptom); versioned VO takes are Phase 2.
  6. **moviepy's extra frames:** not fixed. The moviepy path is frozen as the fallback engine; its
     +1–2 frames per shot stand as measured here.
  7. **Image sequences:** pre-wrapped to a `.mov` at the sequence fps with ffmpeg (via the harness)
     before import; no `rateStretch`. Markers are quantised to the frame grid in the adapter.
     Clip ids: keep dry-run-then-static-script and persist the learned ids beside `cut.jsonl`.
